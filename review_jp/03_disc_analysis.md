# Phase 2-03：日米ディスク解析（日本版「イースI・II」の値の確定）

- 対象ブランチ：`feature/japanese-disc-support`（Phase 1 完了時点 `79c6565`、PCERecomp `1b9d25a`）
- 作成日：2026-11-19
- 方法：**静的解析のみ**。`roms/jp`、`roms/usa`、`roms/bios` を読み取り専用で開き、Python（`.venv/bin/python -I`）で
  セクタ・バイト列の比較と逆アセンブル（`external/PCERecomp/tools/recomp/pcerecomp` の `cdimage`、`disasm`、`opcodes` を読み取り目的で使用）を行った。
  ビルド、ゲームの実行、ダウンロード、パッケージのインストールはしていない。製品コード・CMake・試験・サブモジュールは変更していない。
- 解析スクリプトと出力：`local_analysis/p2_*.py`、`local_analysis/p2_out/`（Git 管理外。ROM 由来の逆アセンブルを含むため）。
- 表記：**[C]** CONFIRMED（日本版のディスク・BIOS のバイト列で直接確かめた）、**[A]** ASSUMPTION（推測）、**[U]** UNKNOWN（不明）。
- 北米版の値は**検索の手がかり**としてだけ使った（ユーザーの決定 P13、1 章）。表に載せた日本版の値は、すべて日本版のバイト列から読んだもの。
- 本書に載せるのは、アドレス・セクタ・CRC・短いシグネチャ（13 バイト以下）などの結論だけ。ROM・BIOS の文章、フォント、画像、長いバイト列は載せない。

## 2. 方法

1. **CUE と指紋**（`p2_disc.py`）：`pcerecomp.cdimage` でトラック配置を求め、`runtime/app/disc_id.c:76-113` と同じ算法で TOC の CRC とデータの CRC を計算した。
   - **算法の検証 [C]**：北米版で計算した値が `disc_id.c:13-15` の定数（43 トラック、TOC `34B2F40E`、データ `EC4E1070`）と一致した。
2. **データトラックのセクタ差分**（`p2_disc.py`）：日米のデータトラックをセクタ単位で比べた。
3. **ローダの逆アセンブル**：常駐ファイル（ファイル 0）の入口表・ローダ・サイズ表を日米で並べて読んだ。
4. **フックの位置**（`p2_hooks.py`、`p2_align.py`、`p2_hookmap.py`）：
   - 北米版で、各フックのシグネチャがどのプログラム／エリアのどの PC で一致するかを確かめた（どのファイルに属するフックかを知るため）。
   - 同じファイルの日米をバイト列で整列させ（`difflib.SequenceMatcher`）、北米版の PC に対応する日本版の PC を求めた。
   - 求めた日本版の PC で、日本版の命令列を逆アセンブルし、北米版と同じ命令の並びであることを目で確かめた。表の日本版シグネチャは、その位置の日本版のバイト列である。
5. **RAM アドレス**（`p2_ram.py`）：北米版の命令のうち絶対・ゼロページの番地を使うものについて、整列した日本版の命令の番地を数えた。
   - 前後のバイトが一致する箇所だけを数える条件でも、バイト単位の整列が命令を 1 つずらして対応づける誤りが残ることを確認した（6.2）。
     そのため、**RAM の値はフックのシグネチャ（日本版のバイト列）に含まれるものだけを [C]** とし、整列だけから得たものは [A] とした。

### 3.2 指紋（U2、`disc_id.c` の算法）

| 項目 | 北米版（検証用） | 日本版 | 状態 |
|---|---|---|---|
| `YS_TRACK_COUNT` | 43 | **43** | [C] |
| `YS_TOC_CRC` | `34B2F40E` | **`D09EEBFB`** | [C] |
| `YS_DATA_CRC` | `EC4E1070` | **`D47ABAE2`** | [C] |
| タイトル文字列 `"Ancient Ys Vanished"`（データトラックの 2 番目のセクタ） | あり（オフセット $6A） | **あり（同じオフセット $6A）** | [C] |

- 結論：日本版は `disc_check_cue()` の「Ys かどうか」の判定を通り、トラック数も一致し、**TOC の CRC で拒否される**（今のコードのまま日本版を渡した場合）[C の値からの推論]。
- データトラックの先頭 2 セクタ（IPL）は日米でバイト単位で同一 [C]。
- 値は Redump 形式（トラックごとの bin）で測ったもの。ほかの形式のイメージ（1 本の bin、ISO+WAV など）で同じ値になるかは [U]（北米版も同じ前提）。

## 6. RAM の配置（U4 の RAM、U12）

### 6.1 帯ごとの結論

### 8.4 PCERecomp との関係

- PCERecomp の `pce_load_cd()` は BIOS のファイルを中身を確かめずに読む（`pce.c:96-121`）[C]。3.0 の追加 RAM（SUPER CD-ROM² の 192 KB）を扱うコードは grep で見つからなかった [C]。
- 「イースI・II」は CD-ROM² のソフトなので追加 RAM は使わない [A]。3.0 が追加 RAM の有無を調べて、ないときにどう振る舞うか、PCERecomp で 3.0 が最後まで起動するかは [U]。**macOS で実行できるようになった後（M3 以降、Phase 3B）で最初に確かめる**。PCERecomp の変更が要るとわかった場合は、変更せずに止めて報告する（作業規則 v2）。
- 北米版の `coverage` の `rom-crc32 FF2A5EC3`（2.0）と照合する `recomp.py disc --check` は、3.0 では拒否される [C の値からの推論]。日本版のカバレッジは 3.0 で記録し直す（`02` の 4.3）。
